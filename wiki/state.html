State и память: от RNN до Mamba, RWKV и Titans

Три разных ответа на один вопрос — «как модель помнит прошлое»: растущий KV-кеш (attention), сжатое состояние фиксированного размера (RNN/SSM/RWKV/RetNet) и явный адресуемый модуль памяти (NTM/DNC/Titans). Разбираем механику каждой и что осталось от классики, а что появилось только недавно.

Три парадигмы «памяти» модели — как растёт объём хранимого
По горизонтали — обработанные токены; высота/размер — сколько модель хранит о прошлом

Это три принципиально разных инженерных ответа на один вопрос, и вся заметка ниже — по сути разбор того, как каждый из них эволюционировал по отдельности.

00Три парадигмы «памяти» модели

Прежде чем идти по истории — важно развести три вещи, которые в разговоре часто смешивают под одним словом «память».

ПарадигмаЧто хранитсяРазмер со временемРазделы
Растущий кеш (attention)явное представление каждого прошлого токеналинейно растётсм. заметку Attention
Сжатое состояние (RNN-семейство)одно «резюме» всей истории, обновляемое на каждом шагеконстантный§01–10 этой заметки
Внешняя адресуемая памятьотдельный банк слотов, к которым обращаются явно, по содержимому или позицииобычно константный (фикс. число слотов) или управляемо растущий§11–16 этой заметки
Все три подхода не взаимоисключающие — современные архитектуры всё чаще комбинируют их (RWKV-state + внешняя Titans-память, или attention + retrieval-память) — об этом отдельно в §19 применительно к NOVA TITAN.

01Vanilla RNN

legacy как backbone

Самый простой рекуррентный механизм: на каждом шаге состояние обновляется как функция от предыдущего состояния и текущего входа.

Vanilla RNN
ht = tanh(Wh·ht-1 + Wx·xt + b)
Проблема, которая ограничила глубину практического применения: при backpropagation through time градиент проходит через одну и ту же матрицу Wh многократно (по числу шагов). Если её собственные значения >1 — градиент взрывается, если <1 — исчезает. На последовательностях в сотни шагов vanilla RNN практически не может выучить зависимости дальше десятков токенов назад.
ранние seq2seq (до 2014)

02LSTM — гейты и «постоянная ошибочная карусель»

legacy как backboneидея гейтов жива везде

Hochreiter & Schmidhuber, 1997. Решение проблемы vanishing gradient — завести отдельную «ячейку памяти» ct, которая обновляется не умножением, а сложением, регулируемым обучаемыми гейтами.

LSTM — три гейта
ft = σ(Wf[ht-1,xt])  // forget gate — что забыть из c
it = σ(Wi[ht-1,xt])  // input gate — что записать
ct = ft⊙ct-1 + it⊙tanh(Wc[ht-1,xt])  // сложение, а не умножение — ключевое отличие от vanilla RNN
ot = σ(Wo[ht-1,xt]),   ht = ot⊙tanh(ct)  // output gate

Идея forget-gate ≈1 в нужные моменты — та же самая «constant error carousel»: если ft≈1, градиент через ct=ct-1+... проходит почти без затухания на много шагов назад — прямой концептуальный предок residual-connection в Transformer (см. заметку Transformer §00).

Почему как backbone для языковых моделей вытеснен: обновление ht зависит от ht-1 — обработка строго последовательна, не распараллеливается по времени при обучении. На длинных последовательностях и больших датасетах это стало основным узким местом относительно Transformer, который параллелится по всем токенам сразу.
seq2seq машинный перевод (до 2017)идея гейтов — во всех GLU-вариантах (см. заметку MLP §06) и в RWKV/Mamba (§06–08 ниже)

03GRU — упрощение LSTM

legacy

Cho et al., 2014. Объединяет forget и input гейты в один update-гейт, убирает отдельную cell-память ct — меньше параметров, обучается немного быстрее, качество на большинстве задач сопоставимо с LSTM.

GRU
zt = σ(Wz[ht-1,xt])  // update gate
ht = (1−zt)⊙ht-1 + zt⊙h̃t  // линейная интерполяция старого и нового состояния
Форма zt⊙new + (1−zt)⊙old — это тот же математический паттерн, что повторится в RWKV decay (§08) и в Titans memory update (§15): линейная интерполяция между «сохранить как было» и «заменить новым», регулируемая обучаемым коэффициентом.
seq2seq (2014–2017)

04Мост к современности: linear attention как рекуррентность

концептуальная основа §05–09

Заметка Attention (§07) уже показывала: linear attention можно переписать в рекуррентной форме. Это ключевой мост между «классическими RNN» (§01–03) и современными state-моделями (§05–09) — они формально принадлежат одному семейству.

Linear attention ≡ матричная рекуррентность
St = St-1 + φ(kt)vtᵀ  // S — матрица d×d, а не вектор — «состояние» большего размера, чем у классического RNN
yt = φ(qt)ᵀSt

Отличие от vanilla RNN — не качественное, а по устройству: состояние S — не вектор, а матрица (внешнее произведение ключей и значений), и никакой нелинейности внутри рекуррентности нет (в отличие от tanh в RNN) — это то, что делает возможным эффективное параллельное вычисление при обучении (parallel/chunkwise формы, см. §08–09).

05S4 и HiPPO: рекуррентность из теории управления

как самостоятельная модельоснова Mamba

Gu et al., 2021. Другая родословная — не от RNN, а от классических непрерывных линейных динамических систем теории управления.

Непрерывная state-space модель
h'(t) = A·h(t) + B·x(t)  // A, B — матрицы, обучаемые или заданные
y(t) = C·h(t)  // линейный readout из состояния

HiPPO (2020, предшественник S4) — способ инициализировать матрицу A так, чтобы состояние h оптимально (в некоторой математически строгой мере) сжимало всю историю входа в фиксированную размерность — не эвристика, а решение конкретной задачи наилучшего онлайн-сжатия функции по ортогональным полиномам.

Ключевая инженерная находка S4 — дискретизация + структурированная параметризация A (диагональная плюс низкоранговая, DPLR), которая позволяет вычислять рекуррентность как свёртку при обучении — эффективно на GPU, в отличие от честного пошагового RNN.

Почему S4 сам по себе не стал массовым LLM-backbone: матрицы A, B, C в исходном S4 не зависят от входа — модель не может «решать», что запомнить, а что забыть, исходя из содержимого конкретного токена. Именно это ограничение снял Mamba (§06).
S4задачи с очень длинными последовательностями (аудио, геномика) до эпохи Mamba

06Mamba — Selective State Space (S6)

mainstream

Gu & Dao, 2023. Главное изменение относительно S4 — сделать A, B, C (и, что важнее, шаг дискретизации Δ) функциями входа, а не константами.

Selective SSM
Bt, Ct, Δt = f(xt)  // линейные проекции входа — теперь параметры рекуррентности зависят от содержимого токена
ht = Ātht-1 + B̄txt  // Ā, B̄ — дискретизированные версии, тоже зависят от t через Δₜ

Δt (шаг дискретизации) — центральный рычаг selectivity: большой Δt заставляет модель «сильно впитать» текущий вход и частично забыть прошлое состояние, маленький — почти проигнорировать вход и сохранить состояние как было. Это в точности механизм «что важно запомнить, а что пропустить», которого не хватало S4.

Цена selectivity — теряется возможность выразить рекуррентность как обычную свёртку (она зависит от входа на каждом шаге). Решение авторов — hardware-aware parallel scan: специальный алгоритм и CUDA-ядро, вычисляющие рекуррентность параллельно по времени через ассоциативное сканирование, а не последовательно шаг за шагом.
MambaJamba (гибрид с attention)Codestral Mamba

07Mamba-2 и Structured State-Space Duality

emerging

Dao & Gu, 2024. Главный результат — не просто ускорение, а теоретическое доказательство: selective SSM и linear attention (§04) — частные случаи одной и той же алгебраической структуры (SSD, structured state-space duality) при определённой параметризации.

Практическое следствие теоремы: Mamba-2 использует скалярный (не входозависимый по каждой размерности отдельно, а один общий на голову) вариант Δ — это упрощение, которое звучит как шаг назад относительно полной selectivity Mamba-1, но именно оно позволяет вычислять рекуррентность через быстрые matmul-примитивы (как attention), а не специализированный scan — на практике заметно быстрее на современных GPU.
Mamba-2

08RWKV: эволюция WKV от v4 до v7

emerging

RWKV развивалась отдельной линией от S4/Mamba — из сообщества, явно вдохновлённого желанием совместить RNN-эффективность инференса с Transformer-эффективностью обучения. Механизм заметно менялся от версии к версии.

ВерсияКлючевое изменение
RWKV-4базовый WKV: константный по каналу decay + экспоненциальное взвешивание прошлых k,v (см. формулу в заметке Attention §10)
RWKV-5 (Eagle)переход от скалярного state к матричному (как в linear attention §04) — больше «ёмкость» на канал
RWKV-6 (Finch)data-dependent decay — то же принципиальное изменение, что Mamba внесла относительно S4: decay теперь зависит от входа, а не константа
RWKV-7 (Goose)обобщённая матрица перехода состояния (generalized delta rule) — ещё более выразительное обновление state, ближе по духу к полноценной SSD (§07)
Заметный паттерн: RWKV, Mamba и линия «RNN→LSTM→GRU» независимо друг от друга пришли к одной и той же идее — data-dependent (selective) обновление состояния лучше константного. Это не совпадение, а, по сути, заново открытая необходимость гейтов (§02) на новом витке архитектур.
RWKV-4/5/6/7

Microsoft, 2023 (кратко разобран и в заметке Attention §12) — здесь глубже про главную инженерную идею: одна и та же математика вычисляется тремя разными способами в зависимости от того, что нужно — обучение или инференс.

10Память при инференсе: во сколько раз меньше, чем KV-кеш

Объём хранимого «прошлого» при росте числа обработанных токенов
Условные единицы, лог-шкала по Y. Внешняя память показана с фиксированным числом слотов — конкретный размер зависит от конфигурации, здесь для примера.
Attention KV-кеш — растёт линейно State (RWKV/Mamba/RetNet) — константа Внешняя память с фикс. числом слотов — константа большего размера
Ось разделяет два независимых вопроса: «сколько байт хранится» (этот график) и «сколько информации реально доступно модели при ответе» (качество/recall) — константный размер не означает автоматически потерю качества, но означает, что вся история сжимается в фиксированный «бюджет», в отличие от honest KV-кеша, который в принципе хранит всё.

11Внешняя память: Memory Networks, NTM, DNC

legacy как архитектураидея адресации жива в Titans

Параллельная (2014–2016) линия исследований, независимая от attention/RNN: явно отделить «вычислительный модуль» (контроллер) от «модуля памяти» — банка слотов, к которым контроллер обращается через операции чтения/записи, как процессор к RAM.

Memory Networks (Weston et al., 2014)

  • Внешняя память как набор векторов фактов; чтение — через что-то вроде attention по содержимому (predecessor самой идеи attention над памятью)

Neural Turing Machine (Graves et al., 2014)

  • Явные read/write головы, дифференцируемая адресация: content-based (по похожести на текущий query, как в attention) и location-based (сдвиг относительно предыдущей позиции чтения — аналог указателя в обычной памяти компьютера)

Differentiable Neural Computer (Graves et al., 2016) добавил к NTM явное отслеживание использования памяти (usage-based allocation — какие слоты свободны) и temporal linkage (в каком порядке что записывалось) — попытка воспроизвести структуры данных вроде связных списков внутри дифференцируемой памяти.

Почему как самостоятельная архитектура не прижилась в языковых моделях: сложные, нестабильные при обучении механизмы адресации плохо масштабировались, а обычный attention над растущим контекстом (KV-кеш) на практике решал ту же задачу проще и с лучшим масштабированием на доступном на тот момент железе. Идея явной, обучаемой read/write адресации, впрочем, вернулась почти десятилетие спустя в Titans (§15).

12KV-кеш как имплицитная память

Стоит явно назвать то, что часто остаётся неявным: обычный attention с растущим KV-кешем — это тоже архитектура внешней памяти, просто с максимально простой политикой — «хранить абсолютно всё, адресовать через content-based attention», без всякого явного контроллера принятия решений о том, что забыть.

Подробный разбор того, как эту «память» можно сжимать (квантование, MQA/GQA/MLA) — в заметках Attention (§08, §14) и Embeddings (§10) применительно к retrieval. Здесь важно другое: любая техника сокращения KV-кеша (§08 заметки Attention) — это фактически движение от парадигмы «хранить всё» к парадигме «сжатое состояние» (§01–09 этой заметки) — граница между «attention» и «state» на практике более размыта, чем кажется по названиям.

13Retrieval-augmented память: kNN-LM, Memorizing Transformers, RETRO

mainstream (в основном как RAG, см. Embeddings)

Ещё один путь к «памяти сверх контекстного окна»: не пытаться сжать всю историю в state и не хранить её в KV-кеше, а вынести в отдельное, потенциально огромное внешнее хранилище и доставать оттуда релевантное по запросу — по сути, retrieval из заметки Embeddings, применённый не к внешним документам, а к собственной памяти модели.

МетодИдея
kNN-LM (Khandelwal et al., 2019)интерполировать предсказание модели с распределением, полученным через kNN-поиск по датастору пар (контекст, следующий токен) — не нужно дообучать модель, чтобы «запомнить» новые данные
Memorizing Transformers (2022)явный слой k-NN attention к внешней (не обучаемой градиентом, просто растущей) памяти прошлых key-value пар — модель «помнит» весь пройденный за жизнь текст, а не только текущее окно
RETRO (DeepMind, 2022)ретривит похожие текстовые чанки из огромного корпуса (не из собственной истории диалога) и подмешивает их через cross-attention — способ дать маленькой модели знания, которые иначе пришлось бы «запоминать» в весах
Общая идея, которая объединяет эти методы с RAG (заметка Embeddings §15) — параметрическая память (то, что выучено в весах модели) и непараметрическая память (то, что достаётся поиском из внешнего хранилища на лету) — не конкурирующие, а взаимодополняющие механизмы: первая даёт общие способности и стиль, вторая — точные, легко обновляемые факты.
kNN-LMMemorizing TransformersRETRO

14Compressive Transformer и Recurrent Memory Transformer

largely legacy

Промежуточный путь между «выбросить старый контекст» и «хранить всё»: старые токены не удаляются и не хранятся честно, а сжимаются в компактное представление меньшего размера при выходе за пределы окна.

Compressive Transformer (DeepMind, 2019)

  • Токены, выпадающие из обычного окна внимания, не отбрасываются, а сжимаются (напр. через 1D-свёртку или pooling) в отдельную «сжатую память» меньшего размера, к которой тоже применяется attention

Recurrent Memory Transformer (2022)

  • Вводит обучаемые «memory-токены», которые передаются от одного сегмента последовательности к следующему — фактически рекуррентность на уровне сегментов, а не отдельных токенов
Почему в основном вытеснены: рост доступной длины контекста напрямую (через эффективный attention, RoPE-scaling, YaRN — см. заметки Attention и Positional) во многих случаях снял саму потребность в сжатии — проще честно обработать более длинный контекст, чем поддерживать отдельный механизм сжатия старой информации.

15Titans: память, которая учится прямо на инференсе

emerging, 2024

Уже разбирался в заметке Attention §13 — здесь глубже про механику и про то, как это соотносится с историей §01–14 выше. Ключевое отличие Titans от всего перечисленного: память — это не банк векторов и не KV-кеш, а небольшая нейросеть (MLP), чьи веса обновляются градиентным шагом прямо во время инференса.

Surprise-based update (повтор из заметки Attention, с акцентом на связь с §01–04)
St = η·St-1 − γt·∇ℓ(Mt-1; xt)  // S — momentum «удивления»; та же роль, что gate в LSTM/GRU
Mt = (1−αt)·Mt-1 + St  // M — веса memory-MLP; forget-подобная интерполяция, как в §02–03
Titans закольцовывает всю историю заметки: forget-gate LSTM (§02) → update-gate GRU (§03) → data-dependent decay Mamba/RWKV (§06, §08) → и теперь αt Titans — один и тот же математический паттерн («сохранить часть старого + добавить часть нового, оба коэффициента обучаемы и зависят от входа»), заново изобретаемый на каждом витке архитектур с 1997 года.

Что принципиально новое

  • «Ёмкость» памяти не фиксирована размером вектора/матрицы состояния — это веса целой сети, потенциально сколь угодно выразительной
  • Обучение памяти происходит на инференсе, а не только во время претрейна — ближе к тому, как человек запоминает новое в моменте

Открытые вопросы

  • Стабильность градиентного обновления весов «на лету» в длинном диалоге — вопрос, для которого пока меньше проверенной практики, чем для константного-размера state (§01–09)
  • Дополнительный compute на каждый токен (вычисление ∇ℓ) по сравнению с простым умножением/сложением в RWKV/Mamba

16Memory-контроллеры и адресация: сводный взгляд

Через всю заметку проходит один и тот же вопрос — «что читать/писать и когда» — который каждая архитектура решает своим механизмом адресации.

МеханизмТип адресацииГде встречается
Content-based (по похожести)читать то, что похоже на текущий query — как в attentionMemory Networks, NTM (частично), attention/KV-кеш, retrieval-память
Location-based (по позиции/сдвигу)обращаться по индексу или сдвигу относительно предыдущего чтенияNTM, DNC (temporal linkage)
Gate-based (скалярный/векторный гейт)решение «сколько сохранить / сколько заменить» на каждый канал состояния, без явного «адреса»LSTM, GRU, RWKV, Mamba (через Δ)
Learned surprise (градиентный сигнал)«интересность» входа определяется через величину градиента внутренней ошибки предсказанияTitans
Первые два типа адресации (content/location) — это «явная память» в духе процессора и RAM; вторые два (gate/surprise) — «неявная память», растворённая в самом процессе обновления состояния, без отдельного понятия «слота» вообще. Выбор между ними — по сути выбор между интерпретируемостью/точным контролем и простотой/эффективностью.

1997
LSTM

Гейты и сложение вместо умножения решают vanishing gradient — идея, которая будет заново открываться следующие 25+ лет.

2014
GRU, Memory Networks, Neural Turing Machine

Упрощение гейтов (GRU) и, параллельно, первая явная внешняя дифференцируемая память (NTM/MemNN).

2016
Differentiable Neural Computer

Усложнение NTM: usage tracking, temporal linkage — попытка воспроизвести структуры данных внутри нейросети.

2017
Transformer вытесняет RNN как backbone

Параллелизуемость обучения перевешивает теоретическую элегантность рекуррентности.

2019
Compressive Transformer, kNN-LM

Два разных пути к памяти сверх окна: сжатие старого контекста и retrieval из внешнего хранилища.

2021
S4

Рекуррентность возвращается — на этот раз из теории управления, с эффективным параллельным обучением через свёртку.

2022
RETRO, Memorizing Transformers, RWKV-4

Retrieval-память на масштабе; RWKV начинает собственную линию развития linear-recurrence.

2023
Mamba, RetNet

Selective SSM и retention — оба независимо приходят к необходимости data-dependent обновления состояния.

2024
Mamba-2 (SSD), RWKV-6/7, Titans

Теоретическое объединение linear attention и SSM; RWKV догоняет selectivity; внешняя обучаемая-на-тесте память возвращается на новом уровне.

Почему конкретно отказались

Vanilla RNN / LSTM / GRU как backbone LLM

  • Строго последовательное обучение не параллелится по времени — Transformer выигрывает по эффективности обучения на доступном железе

S4 без selectivity

  • Input-independent A/B/C не позволяют модели решать, что запомнить — Mamba показала, что это решаемо без потери эффективности

NTM / DNC как целостная архитектура

  • Сложная, нестабильная адресация плохо масштабировалась; attention над KV-кешем решал ту же задачу проще на тогдашнем железе

Compressive Transformer / RMT

  • Рост доступной длины контекста напрямую (эффективный attention + RoPE-scaling) во многих сценариях снял саму потребность в сжатии старого контекста

19Как это соотносится с NOVA TITAN

Заметка специально под текущий стек: RWKV-state (§08) + local linear attention (§04) + Titans-модуль (§15) в контроллере/памяти.

state.py — RWKV-подобная рекуррентность закрывает «средний горизонт» дёшево §08 §10

Судя по константному размеру состояния (§10), RWKV-часть — правильный кандидат на «Working»-уровень: быстрый, дешёвый по памяти доступ к недавнему контексту без растущего KV-кеша. Стоит явно решить, какую версию WKV использовать (v4 vs v6/v7) — data-dependent decay (v6+) даёт больше выразительности, но и больше compute на шаг.

controller.py + memory.py — это ровно вопрос §16 (адресация) §11 §16

При проектировании трёхуровневой памяти стоит явно решить, какой тип адресации использует каждый уровень: content-based (attention-подобный поиск по содержимому) для Long-памяти vs gate-based (как в §02–03, §08) для Short — это разные, отдельно настраиваемые компоненты, а не одна общая политика на всю систему.

Titans-модуль ближе к NTM/DNC по духу, чем к RWKV/Mamba §11 §15

Стоит явно опираться на историю NTM/DNC (§11) при проектировании controller.py — усложнения вроде usage-based allocation и temporal linkage, которые DNC добавил поверх NTM, могут быть релевантны при масштабировании Titans-памяти до тысяч/миллионов записей, даже если сам Titans этого явно не описывает.

Retrieval-память (§13) — запасной путь, если Titans окажется нестабильным на практике §13

Если градиентное обновление весов памяти «на лету» (§15) окажется сложным для стабильного обучения, подход в духе kNN-LM/Memorizing Transformers — явное хранилище прошлых состояний + retrieval по содержимому — более консервативная, проверенная временем альтернатива для Long-уровня.
